# 本地日记成长回顾

## 项目入口

当前产品范围已调整：用户取消多年对照，要求对所选文件逐年生成独立的日记状态回顾。年度回顾描述表达的情绪、关注与压力、应对与支持及年内变化，不作精神疾病诊断。旧产品设计的年度比较仅为历史规划，不主动实现。词频不能代替语义总结；需要语义分析时使用本机离线模型，缺少模型时先说明工具下载和资源需求，不把规则统计冒充年度精神状态结论。

技能位于脚本文件夹的 `skills/local-diary-review/`。从本技能目录向上两级找到 `diary_insights.py` 和 `使用说明.txt`，不复制另一份分析代码。
需要设计跨年功能时，阅读 [产品设计](references/product-design.md)。其中“规划”不能当作已实现功能。

当前脚本支持单个 .docx 或递归扫描文件夹，jieba 分词、本地 HTML 报告、词频和时间线 CSV。运行方式：`py -3.13 diary_insights.py "本地文件或文件夹"`；无参数时选择文件夹；`--no-open` 不打开浏览器，`--output` 指定报告父目录。先验证解释器和依赖可用，不假设任意设备安装路径相同。

年度语义回顾的入口是同目录 `annual_diary_review.py`，参数为 `日记文件夹 --output 报告父目录`，可用 `--resume 已有报告目录` 复用本地中间结果。它调用固定本机端口 `127.0.0.1:11439` 的 `qwen3:4b`，不允许远程地址、环境代理或重定向。按年输出草稿、引用和原文，逐字引用检查不能证明语义解释正确。当前只扫描指定目录顶层 .docx。

本机部署位置为 `E:\可视化日记`：`models/` 存模型，`tools/ollama/` 存独立运行工具，`tools/diary_app/` 是上述 Python 脚本的运行副本，`reports/` 存结果。开发修改源脚本后，核对差异再同步对应运行副本。`start_local_model.ps1` 强制禁用云端，只监听回环地址；不设置全局用户环境变量。开始真实分析前确认模型下载完整、服务来源为该目录、云端禁用有效且通过合成文本测试。

## 用户的持续约束

- 日记正文、摘录、关键词、人名、情绪推断及报告都只能留在本机。不要通过云端模型、网页、连接器或聊天工具输出传递这些数据。执行本地分析时只返回成功状态、错误类型和输出路径；不要把正文或含原文的异常日志回显给助手。
- 不删除或覆盖原始日记。默认每次新建报告目录；不自动扫描用户未指定的目录。
- 无远程字体、图表 CDN、遥测或外部分析接口。依赖安装与日记处理分开；分析必须能断网运行。不要以本地模型名义调用远程推理。
- 不擅自发布、同步、分享或安装到全局技能目录。报告含敏感内容；输出位置沿用用户指定位置或当前脚本默认位置，不能声称已确认磁盘不受网盘同步。

## 分析的真实性

- 文件数量不等于年份数量。用户有 2020—2026 年日记，但可能只有 6 份文件，按日期覆盖范围核对，不臆造缺失年份。
- 缺少日期进入待确认区；日记日期不等于事件日期；正文回忆不能自动归入写作当天发生的事件。
- 跨年比较同时展示字数、记录天数、日期覆盖率和归一化指标。少写不等于少经历，没有记录不等于零。
- 自动主题标签和里程碑是候选结果，应能查看来源、修正和取消。引文保留来源文件及段落标识。
- 不生成成长总分、心理诊断或无证据的因果结论；情绪标注不得直接等同真实情绪。

## 扩展与验证

先核对现有代码，再按用户本次范围实现；只做产品设计时不要顺带实现完整程序。手工标签、日期修正和去重决定应独立保存，重跑分析不得丢失。
用合成日记验证多文件跨年、缺失日期、重复文件、非完整年份、HTML 转义和原文件不变。不使用真实日记内容制作提交给助手或外部工具的截图、样例或测试快照。
新增依赖优先考虑能离线部署的组件；运行错误仅输出脱敏信息。完成后分别说明已实现、已验证、仍属规划的部分。
